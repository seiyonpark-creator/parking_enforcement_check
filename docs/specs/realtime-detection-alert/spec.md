# 실시간 감지 보조 알림

> **superseded by [three-source-parking-view](../three-source-parking-view/spec.md).**
> 실시간 감지는 배너가 아니라 다른 두 데이터셋과 나란히 목록+마커로 표시하는
> 방식으로 바뀌었다. 데이터 출처와 키 처리 방식은 여전히
> [realtime-detection-source](../../decisions/realtime-detection-source.md)를
> 따른다. 이 파일은 과거 기록으로만 남긴다.

## 사용자 결과

사용자가 t-data.seoul.go.kr의 V2X 감지 지점(현재 서울 강서구 등촌동~염창동 부근
5곳) 근처에 있을 때, 방금 감지된 불법주정차 알림을 추가로 확인할 수 있다.

## 승인된 범위

- 위치 조회에 성공하면, 기존 이력 조회·지도 표시와 별도로 t-data.seoul.go.kr의
  최신 V2X 감지 데이터를 조회한다.
- 감지 지점 중 사용자의 현재 위치로부터 반경 300m 이내이면서, 그 지점의 가장
  최근 감지 시각이 5분 이내인 경우에만 화면에 알림을 보여준다.
- 알림 문구에는 이 기능이 일부 지점에서만 동작한다는 점을 명시해, 알림이
  없다고 해서 "이 근처가 안전하다"로 오해하지 않도록 한다.
- `TDATA_API_KEY` 서버 환경변수가 없으면 이 기능과 관련된 요청 자체를
  생략한다. 나머지 기능(이력 조회, 지도, 도로명 주소 표시)은 영향받지 않는다.
- t-data.seoul.go.kr 호출이 실패해도(네트워크 오류, 인증 실패, 요청 제한 등)
  기존 화면은 그대로 동작하고 이 알림만 조용히 생략된다.

## 관찰 가능한 수용 기준

1. `TDATA_API_KEY`가 설정된 상태에서, 현재 위치가 감지 지점 반경 300m 이내이고
   그 지점의 최신 감지 시각이 5분 이내이면 화면에 실시간 감지 알림이 나타난다.
2. 같은 조건에서 최신 감지 시각이 5분보다 오래됐거나 반경 밖이면 알림이
   나타나지 않는다.
3. `TDATA_API_KEY`가 없으면 이 알림은 전혀 나타나지 않고, 이력 조회·지도·주소
   표시는 이전과 동일하게 동작한다.
4. t-data.seoul.go.kr 호출이 실패해도 기존 화면(이력, 지도)은 오류 없이 정상
   동작한다.
5. 알림 문구에는 이 기능의 좁은 커버리지를 알리는 문구가 포함되어 있다.

## 확정된 제약과 이유

- t-data.seoul.go.kr V2X 데이터를 실시간 보조 알림의 출처로 쓴다
  ([realtime-detection-source](../../decisions/realtime-detection-source.md)).
- 인증키는 서버 환경변수로만 두고 소스에 커밋하지 않는다. 사용자 개인 계정에
  연결된 키이기 때문이다.
- 반경은 기존 이력·지도 기능과 같은 300m를 그대로 쓴다. 새 기준을 따로 만들
  이유가 없기 때문이다.
- 이 기능은 기존 기능을 절대 깨뜨리지 않는다: 키가 없거나 외부 호출이
  실패해도 나머지 화면은 항상 정상 동작해야 한다.

## 가정

- 신선도 기준은 "가장 최근 감지 시각이 5분 이내"로 잡는다. 실제 데이터에서
  차량이 감지된 채 몇 분~몇십 분씩 연속으로 핑을 보내는 패턴을 봤을 때, 5분은
  "아직 그 자리에 있을 가능성이 높다"고 볼 수 있는 보수적인 기준이다.
- 서버는 t-data.seoul.go.kr 호출 결과를 짧게(예: 15초) 캐시해서, 여러 사용자가
  동시에 조회해도 t-data.seoul.go.kr의 반복 호출 제한(10초)에 걸리지 않게 한다.
- 알림은 별도 지도 마커 없이, 기존 화면 상단에 Alert 형태로만 보여준다. 지도에
  감지 지점을 항상 표시하는 것은 범위 밖이다(아래 참고).

## 범위 밖 (이유)

- 지도에 5개 감지 지점을 상시 표시 — 커버리지가 서울 극히 일부에 불과해,
  상시 표시하면 마치 이 서비스가 실시간 감지를 폭넓게 지원하는 것처럼 오해할
  수 있다. 감지 지점 근처에 실제로 있을 때만 알림으로 노출한다.
- 폴링이나 자동 새로고침으로 알림을 계속 최신 상태로 유지 — 기존 파일럿과
  동일하게 1회 조회 결과를 기준으로 한다.
- 다른 사용자를 위한 공용 API 키 제공 — 인증키는 사용자 개인 계정에 연결돼
  있어 공유할 수 없다.
- 신선도 기준(5분)이나 반경을 사용자가 직접 조정하는 기능 — 이번 범위에서는
  고정값으로 둔다.

## 유보된 결정

- V2X 센서 배치가 확대되면 이 알림을 지도 상시 표시나 더 큰 기능으로 승격할지는
  [realtime-detection-source](../../decisions/realtime-detection-source.md)의
  재검토 조건이 충족될 때 다시 다룬다.
- 신선도 기준(5분)과 반경(300m)을 조정 가능하게 할지는 다음 단계에서 정한다.

## 남은 위험

- t-data.seoul.go.kr의 하루 최대 1,000건, 10초 반복 호출 제한을 짧은 캐시만으로
  충분히 피할 수 있는지는 실제 트래픽에서 확인이 필요하다.
- 감지 지점이 현재 5곳뿐이라, 실제로 이 알림이 뜨는 상황을 재현하려면 그 중
  한 곳 좌표를 직접 넣어 검증해야 한다(실제 위치가 우연히 그 근처일 가능성은
  낮음).

## 연결된 소스

- [parking-data-source](../../decisions/parking-data-source.md) — t-data.seoul.go.kr을
  조사하게 된 배경과 실제 호출 근거.
- [realtime-detection-source](../../decisions/realtime-detection-source.md) — 이
  기능에서 t-data.seoul.go.kr을 쓰는 이유와 인증키 처리 방식.
- [nearby-enforcement-map spec](../nearby-enforcement-map/spec.md) — 이 알림이
  추가되는 기존 화면(이력 목록·지도)의 수용 기준.

이 스펙에 없는 세부 규칙은 위 소스가 갖고 있으므로, 구현 시 함께 참고한다.
