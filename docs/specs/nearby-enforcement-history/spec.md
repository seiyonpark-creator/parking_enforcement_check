# 현재 위치 근처 단속 이력 조회

## 사용자 결과

사용자는 지금 자신이 있는 위치를 기준으로, 근처에서 실제로 있었던 최근 주정차 단속 이력을 확인할 수 있다.

## 승인된 범위

- 브라우저 GPS로 현재 위치 좌표를 얻는다.
- 서울시 불법주정차 단속 정보(OA-22190) 중 2025년 4분기(10~12월) CSV 파일 하나를 데이터 출처로 사용한다.
- 현재 좌표를 기준으로 반경 300m 이내의 단속 이력을 거리순으로 정렬해 리스트로 보여준다.
- 각 이력 항목은 단속일시, 단속주소를 보여준다.
- 결과 없음, 위치 조회 거부, 조회 중이라는 세 가지 상태를 화면에서 각각 구분해 보여준다.

## 관찰 가능한 수용 기준

1. 위치 정보 제공을 허용하면, 몇 초 안에 반경 300m 이내 이력 리스트(또는 이력 없음 안내)가 화면에 나타난다.
2. 리스트의 각 항목에 단속일시와 단속주소가 사람이 읽을 수 있는 형태로 표시된다.
3. 위치 정보 제공을 거부하거나 브라우저가 위치 조회를 지원하지 않으면, 재요청 방법을 안내하는 문구가 뜨고 리스트는 비어 있다.
4. 조회 중에는 로딩 상태가 표시되고, 조회가 끝나기 전에 빈 리스트나 오류처럼 보이는 화면이 뜨지 않는다.
5. 반경 300m를 벗어난 이력은 리스트에 나타나지 않는다.

## 확정된 제약과 이유

- 서울시 지역 한정, 로그인·계정 없이 사용한다 (PRODUCT.md 경계를 계승).
- 한 번에 확인하는 위치는 사용자의 현재 위치 하나다 (PRODUCT.md 경계를 계승).
- 정보의 정확성과 신뢰성을 우선한다. 단속 이력의 일시·주소는 원본 CSV 값을 그대로 보여주고 임의로 가공하거나 추정하지 않는다.
- 데이터 출처는 OA-22190의 최신 분기(2025 Q4) CSV 파일 하나로 한정한다. 전체 12개 파일(총 800MB 이상)을 한 번에 통합하면 첫 결과물의 구현과 검증이 지연되므로, 가장 최근 데이터로 범위를 좁혔다. 왜 이력 데이터 자체를 쓰는지는 [parking-data-source](../../decisions/parking-data-source.md) 결정 계약을 따른다.
- 결과 화면은 리스트 기반으로 구성하고 지도 시각화는 쓰지 않는다. 위경도 기반 거리 계산과 리스트 표시만으로 "근처에 이력이 있는가"라는 핵심 질문에 답할 수 있어, 지도 없이도 첫 결과물을 검증할 수 있다.
- UI는 기존 UI 구성 원칙([ui-composition](../../decisions/ui-composition.md))을 따른다. 리스트·카드, 빈 상태, 로딩 상태, 오류 상태를 shadcn 구성 요소로 표현한다.

## 가정

- 검색 반경은 300m를 기본값으로 하고, 이후 쉽게 조정할 수 있는 값으로 둔다.
- CSV의 실제 컬럼명과 인코딩은 파일을 내려받아 확인하며, 공개된 설명("단속일시, 단속주소, 위도, 경도")과 일치한다고 가정한다.
- 위경도 기준 반경 필터링은 서버 사이드(또는 빌드 타임에 가공된 데이터)에서 처리하고 브라우저는 결과만 받는다고 가정한다. 정확한 처리 위치는 구현 단계에서 정한다.

## 범위 밖 (이유)

- 실시간·예정 단속 알림 — 확보 가능한 데이터가 이력뿐이라 이번 결과물에서는 불가능하다. [parking-data-source](../../decisions/parking-data-source.md)에서 후속 과제로 명시한다.
- 앱을 닫았을 때의 백그라운드 감시·푸시 알림 — PRODUCT.md 경계에서 이미 범위 밖으로 확정됐다.
- 여러 위치·차량 동시 등록 — PRODUCT.md 경계에서 이미 범위 밖으로 확정됐다.
- 지도 시각화 — 리스트만으로 첫 결과물을 검증할 수 있어 이번 범위에서 제외한다.
- 데이터 자동 갱신·여러 분기 통합 — 이번 결과물은 2025 Q4 파일 하나로 고정한다.
- 로그인·계정, 사용자별 데이터 저장 — PRODUCT.md 경계에서 이미 범위 밖으로 확정됐다.

## 유보된 결정

- 데이터 갱신 방식: 분기가 바뀔 때 파일을 수동으로 교체할지, 자동 파이프라인을 둘지는 다음 단계에서 정한다. 그때까지는 2025 Q4 파일 하나만 반영된 상태로 둔다.
- 검색 반경을 사용자가 직접 조정할 수 있게 할지는 다음 단계에서 정한다. 그때까지는 300m 고정값으로 동작한다.
- 지도 시각화 도입 여부는 다음 단계에서 정한다.
- 실시간 단속 데이터 확보 경로(t-data.seoul.go.kr API 인증 등)는 [parking-data-source](../../decisions/parking-data-source.md)의 재검토 조건이 충족될 때 다시 다룬다.

## 남은 위험

- OA-22190 CSV의 실제 컬럼명·인코딩·결측치 형태는 파일을 내려받기 전까지 확정되지 않았다. 구현을 시작할 때 가장 먼저 확인해야 한다.
- 2025 Q4 파일(약 54MB)이라도 브라우저에서 직접 파싱하면 느릴 수 있다. 서버 사이드 처리나 사전 인덱싱이 필요할 수 있다.
- 이번 결과물은 PRODUCT.md의 "실시간 정보로 단속 위험을 미리 파악한다"는 약속을 이력 조회 수준으로 좁힌 것이다. PRODUCT.md 자체를 이 결정에 맞춰 다시 정리할지는 별도로 검토가 필요하다.

## 연결된 소스

- [PRODUCT.md](../../../PRODUCT.md) — 서울시 한정, 단일 위치, 로그인 불필요, 정확성·신뢰성 원칙의 근거.
- [parking-data-source 결정 계약](../../decisions/parking-data-source.md) — 왜 이력 데이터를 쓰는지, 실시간을 언제 다시 검토하는지.
- [ui-composition 결정 계약](../../decisions/ui-composition.md) — 리스트·카드·상태 표현에 적용할 UI 구성 규칙.

이 스펙에 없는 세부 규칙과 화면 구성은 위 소스가 갖고 있으므로, 구현 시 이 스펙과 함께 반드시 참고한다.
