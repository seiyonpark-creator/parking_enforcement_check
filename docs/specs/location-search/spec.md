# 주소·장소 검색으로 위치 지정

이 스펙은 [three-source-parking-view](../three-source-parking-view/spec.md)가
정의한 화면(현재 위치+지도+3열 목록)에 이어 붙는다. 3열·지도의 수용 기준은
바뀌지 않고, "어떤 좌표를 기준으로 조회할지"를 정하는 방법이 늘어난다.

## 사용자 결과

사용자는 현재 위치(GPS) 대신, 주소나 장소명을 입력해서 그 위치를 기준으로
상시 단속 카메라·단속 이력·실시간 감지 정보와 지도를 확인할 수 있다.

## 승인된 범위

- 화면에 주소·장소를 입력하는 검색창과 검색 실행 방법(버튼 또는 엔터)을
  둔다.
- 페이지에 처음 들어오면 지금과 같이 GPS로 현재 위치를 자동 조회한다. 이
  기본 동작은 바뀌지 않는다.
- 검색어를 제출하면 [location-search-source](../../decisions/location-search-source.md)에
  따라 후보 목록(최대 5개)을 보여준다.
- 후보 하나를 선택하면, 그 좌표를 기준 위치로 삼아 지도 중심과 3열(상시
  카메라/단속 이력/실시간 감지)을 다시 조회한다.
- 검색 결과가 없으면 이를 알리는 문구를 보여준다.
- 검색으로 기준 위치를 바꾼 뒤에도, 다시 현재 위치(GPS) 기준으로 되돌릴 수
  있는 방법을 둔다.
- 화면 상단의 위치 표시는 기준이 현재 위치인지 검색한 위치인지 구분되게
  보여준다.

## 관찰 가능한 수용 기준

1. 검색창에 주소나 장소명을 입력하고 제출하면, 검색 결과 후보 목록이
   나타난다.
2. 후보 중 하나를 선택하면 지도 중심이 그 좌표로 이동하고, 3열의 내용이 그
   좌표 기준으로 갱신된다.
3. 검색어에 맞는 결과가 없으면 "검색 결과가 없습니다" 같은 안내가 뜬다.
4. 검색으로 위치를 바꾼 상태에서, 현재 위치로 되돌리는 조작을 하면 다시
   GPS로 위치를 조회하고 화면이 그 결과로 갱신된다.
5. 검색 위치 기준일 때 화면 상단 표시가 "현재 위치"가 아니라 검색한
   주소/장소 기준임을 구분해서 보여준다.
6. 검색 요청이 실패해도(네트워크 오류 등) 이미 표시 중인 GPS 기준 조회
   결과나 화면은 깨지지 않는다.

## 확정된 제약과 이유

- 주소·장소 검색은 Nominatim search 엔드포인트를 쓰고, 여러 후보가 있으면
  사용자가 직접 고른다
  ([location-search-source](../../decisions/location-search-source.md)).
- 3열과 지도는 [three-source-parking-view](../three-source-parking-view/spec.md)의
  기존 컴포넌트와 API 라우트를 그대로 쓴다. 그 라우트들은 좌표(lat, lng)만
  받으므로, 좌표의 출처가 GPS든 검색이든 구분 없이 동작한다.
- 페이지 진입 시 기본 동작(GPS 자동 조회)은 바뀌지 않는다. 검색은 그 위에
  얹는 대안이지, 기본값을 대체하지 않는다.

## 가정

- 후보 목록에는 Nominatim이 주는 `display_name`을 그대로 보여준다.
- 검색은 대한민국 범위로 한정해서 요청한다(`countrycodes=kr`).
- 검색창은 화면 상단, 기존 위치 표시 영역 근처에 둔다.

## 범위 밖 (이유)

- 입력 중 실시간 자동완성 후보 표시 — 제출 후 후보 목록을 보여주는 것으로
  이번 범위에서는 충분하다.
- 지도를 드래그하거나 클릭해서 위치를 직접 찍는 기능 — 검색 입력만으로
  범위를 좁힌다.
- 최근 검색어 저장, 즐겨찾기 — 이번 범위 밖이다.
- 대한민국 밖 지역 검색 — 이 서비스의 모든 데이터가 서울시 한정이라 의미가
  없다.

## 유보된 결정

- 후보가 여전히 너무 많거나 고르기 번거롭다는 근거가 쌓이면, 자동 선택 방식
  재검토는 [location-search-source](../../decisions/location-search-source.md)의
  재검토 조건을 따른다.

## 남은 위험

- Nominatim 공개 서버의 사용량 정책은 검색 요청에도 동일하게 적용된다.
  이번 파일럿 규모에서는 문제 없지만 [map-library](../../decisions/map-library.md)의
  재검토 조건과 같은 선상에서 지켜봐야 한다.
- 흔한 장소명·상호명은 후보가 많아 사용자가 원하는 곳을 찾기 번거로울 수
  있다. 실제 사용에서 확인이 필요하다.

## 연결된 소스

- [three-source-parking-view spec](../three-source-parking-view/spec.md) — 이
  기능이 이어받는 3열+지도 화면의 수용 기준.
- [location-search-source](../../decisions/location-search-source.md),
  [reverse-geocoding](../../decisions/reverse-geocoding.md) — 검색·주소 변환에
  Nominatim을 쓰는 이유.

이 스펙에 없는 세부 규칙은 위 소스가 갖고 있으므로, 구현 시 함께 참고한다.
